이게 뭔가요? What is this?

일반적인 인사관리 시스템(HRIS)을 흉내 낸 목업 HR입니다. 하나의 SQLite DB를 세 가지 창구로 노출합니다: 사람용 웹 콘솔, 에이전트용 REST API, 에이전트용 MCP 서버. 복제본 부팅 시 init이 hr_core/dataset.json을 읽어 항상 초기화합니다. 부팅 경로에서는 난수를 사용하지 않습니다. 데모 전용이라 실제 보안은 없습니다.

고정 데이터와 이동하는 이력 History

픽스처의 값·식별자·간격은 고정됩니다. 부팅 시 최신 근태일을 기준으로 Δ = 7 × floor((서버 오늘 − 픽스처의 최신 근태일) / 7)만큼 날짜를 함께 옮깁니다. 최신 근태는 오늘보다 0~6일 전이며, 월~금 요일과 출퇴근 시각·근무시간·기록 간 간격이 그대로 유지됩니다. 약 198일의 운영 이력을 91일로 압축하거나 시작을 3개월 전으로 맞추지 않습니다.

근태일, 휴가 시작·종료·신청·결정일, 교육 신청·완료일, 발령일과 입사일이 함께 이동합니다. 생년월일은 이동하지 않으며, 입사일과 입사 발령일은 일치합니다. 휴가 신청일은 시작일 14일 전, 결정일은 7일 전으로 고정 생성하고 신청 상태의 결정일은 비워 둡니다.

연차잔액은 이동한 휴가의 사원·시작 연도별로 다시 계산합니다. 승인 휴가의 일수를 합산하고, 신청·반려를 포함한 모든 휴가에 해당 연도 잔액 행을 만듭니다. 기존 사원별 부여일수는 보존하며, 하나의 휴가를 연도별로 일할 분할하지 않습니다.

HR_HISTORY_START는 첫 근태일을 고정하는 ISO 날짜입니다. 원본과 같은 월요일만 허용하며 다른 요일은 오류로 거부합니다. HR_HISTORY_START=2026-07-06이면 원본 날짜, HR_HISTORY_START=2025-12-22이면 근태가 2025-12-22~2026-01-02에 고정됩니다. 고정 모드의 기본 잔액 연도는 고정된 최신 근태의 연도입니다. 외부 시스템은 재시작 후 절대 날짜를 다시 조회해야 합니다.

픽스처 변경은 유지보수 명령 python -m hr_core.generate --force로만 의도적으로 수행합니다. --force 없이는 덮어쓰지 않습니다. 생성기는 임시 DB를 사용하며 서비스 DB를 건드리지 않습니다.

외부 쓰기와 초기화 Data lifecycle

minReplicas=1로 실행되므로 6분 이상 유휴 상태여도 외부 쓰기가 유지됩니다. 반면 복제본 재시작·재배포·seed 재실행은 초기화입니다. python -m hr_core.seed는 기존 DB가 있어도 모든 HR 테이블을 원자적으로 복원합니다. API/MCP 프로세스만 재시작하고 init을 다시 실행하지 않는 경우에는 초기화하지 않습니다. EmptyDir 저장소이므로 영구 보관은 지원하지 않으며, 상시 실행 비용이 발생합니다.

전체 흐름 Overall flow

  1. 1
    입사

    부서·직급 지정, 연차 자동 부여, 입사 발령 기록

    부서·직급을 지정해 사원을 등록합니다. 등록 시 당해연도 연차가 자동 부여되고 입사 발령이 함께 기록됩니다.

  2. 2
    교육

    수강신청과 이수·미이수 처리

    법정필수·직무·리더십·어학 과정을 수강신청하고 이수/미이수 처리합니다. 법정필수 이수율이 대시보드에 집계됩니다.

  3. 3
    연차·휴가

    신청·승인·반려와 잔여 연차 차감

    휴가를 신청(신청)하고 승인/반려합니다. 승인 시 잔여 연차가 차감되며, 잔여가 부족하면 승인이 차단됩니다.

  4. 4
    근태

    출퇴근 기록과 근무시간·상태 자동 계산

    출근/퇴근을 기록하면 근무·연장 시간과 상태(지각/조퇴/정상)가 자동 계산됩니다.

  5. 5
    인사발령

    승진·이동·휴직·복직·퇴직 반영

    승진·부서이동·휴직·복직·퇴직을 기록하면 사원정보(직급/부서/재직상태)에 즉시 반영됩니다.

Hire ─▶ (연차부여+입사발령) ─▶ Training / Leave(승인시 연차차감) / Attendance ─▶ Appointment(사원정보 반영)

기준정보 CRUD와 삭제 방어

DB·REST·MCP·화면은 같은 쓰기 함수를 사용합니다. 사번과 부서·직급·과정 코드는 수정할 수 없습니다. REST는 목록 주소에 POST, 개별 코드 주소에 PATCH·DELETE를 사용합니다. MCP 수정 도구는 식별자와 changes 객체를 받습니다. 보내지 않은 필드는 유지되고, nullable 필드에 명시한 null은 값을 지웁니다.

참조 중인 기준정보는 Python에서 삭제를 차단합니다. 재직 사원뿐 아니라 퇴직자·하위 부서·관리자·교육·휴가·근태·발령 이력도 검사합니다. REST는 409, MCP는 예외 대신 {"error": "cannot delete ...: still referenced by ..."}를 반환하며 어떤 기록이 몇 건 막는지 알려줍니다. 화면에도 같은 사유가 표시됩니다.

입사로 생성된 연차잔액과 입사 발령도 삭제 방어 대상이므로 새 사원 역시 참조가 있으면 삭제할 수 없습니다. 성공하는 생성→수정→삭제 테스트는 아직 참조가 없는 부서·직급·과정으로 수행할 수 있습니다. 이력을 연쇄 삭제하거나 전체 DB를 원격으로 지우는 기능은 없습니다.

에이전트 연결 Agent access

REST와 MCP는 헤더 X-API-Key: changjuahn가 필요합니다. 웹 콘솔과 /api/docs는 공개입니다.

REST (Employee·Department·Position·Course·Training·Appointment):

curl -H "X-API-Key: changjuahn" https://<fqdn>/api/employees
curl -X POST -H "X-API-Key: changjuahn" -H "Content-Type: application/json" \
     -d '{"name":"홍길동","dept_code":"D110","position_code":"P1"}' https://<fqdn>/api/employees
curl -X PATCH -H "X-API-Key: changjuahn" -H "Content-Type: application/json" \
     -d '{"name":"김대표 외부수정"}' https://<fqdn>/api/employees/E0001

MCP (Attendance·Leave·기준정보 CRUD), streamable HTTP at /mcp with the same header. Operational tools: log_attendance, list_attendance, get_attendance_summary, submit_leave_request, decide_leave_request, get_leave_balance, list_leave_requests, list_employees, get_employee.

사원·부서·직급·과정의 생성·조회·수정·삭제 도구도 제공됩니다. MCP 수정 예시:

{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"update_employee","arguments":{"emp_id":"E0001","changes":{"name":"김대표 외부수정"}}}}

Full REST reference: /api/docs. Full MCP reference (도구 스펙·연결 설정): /mcp-docs.
